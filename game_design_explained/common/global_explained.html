Le mot global

Pourquoi lives -= 1 plante dans une fonction, alors que invaders.append(alien) marche très bien ? Tout est une histoire de deux cahiers : celui du jeu, et le brouillon de la fonction.

1

Deux cahiers

Les variables créées en dehors des fonctions (lives, score, invaders…) sont dans le cahier du jeu. Tout le programme peut les lire.

Quand une fonction est appelée, elle reçoit un brouillon tout neuf. Les variables qu'elle crée vont dedans… et le brouillon est jeté à la fin de la fonction.

Appuie sur « Appeler la fonction » : le brouillon apparaît en bas, puis disparaît.

2

Lire, ça marche

Une fonction peut lire une variable du jeu sans rien faire de spécial. Python ne la trouve pas dans le brouillon, alors il va la chercher dans le cahier du jeu.

def is_dead():
    return lives <= 0     # on lit seulement
3

Modifier : ça plante

Mais dès qu'une fonction écrit lives = … (ou lives -= 1), Python décide : « lives est une variable de mon brouillon ».

Et dans le brouillon, lives n'a encore aucune valeur. Calculer lives − 1 est impossible :

UnboundLocalError: lives# « je ne connais pas encore lives dans ce brouillon »

Le message exact peut varier dans Codesters, mais l'idée est la même.

4

global : écrire dans le cahier du jeu

En haut de la fonction, global lives veut dire : « quand je parle de lives, c'est celle du cahier du jeu, pas une nouvelle dans mon brouillon ».

def player_hit(sprite, hit_sprite):
    global lives
    lives -= 1

Regarde la flèche : la fonction modifie directement la case du jeu.

5

Les listes : pas besoin

invaders.append(alien) n'écrit pas invaders = … : on ne change pas l'étiquette, on range quelque chose dans la liste qu'elle désigne.

Python lit donc invaders dans le cahier du jeu, comme à l'étape 2, et la liste grandit. Pas besoin de global.

Pareil pour invaders.remove(…), player.set_x(…), boss.hide()…

6

Le piège : = []

Pour vider la liste au début d'une nouvelle partie, on pourrait écrire invaders = [] dans une fonction.

Mais c'est un = : Python crée une nouvelle liste vide dans le brouillon… qui est jeté à la fin. La vraie liste du jeu n'a pas bougé, et il n'y a aucune erreur pour prévenir.

Avec global invaders en haut de la fonction, le problème disparaît.

7

La règle

Dans une fonction, j'écris…global ?
print(lives)non, on lit
lives -= 1oui
score = score + 10oui
invaders.append(alien)non, on range
invaders = []oui
lives_display = codesters.Text(…)oui

En résumé : un nom du jeu à gauche d'un = (ou de +=, -=) dans une fonction → global ce nom.
